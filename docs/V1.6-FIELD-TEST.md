# Scoutline Version 1.6 field-test release

Version 1.6 is the completed front-to-back match workflow intended for the next real-life test. Feedback from that test and planned broader development belongs to Version 2.

## Pre-deployment configuration

Add the following environment variable to the Vercel project for Production, Preview and Development:

- `OPENAI_API_KEY` — a server-side OpenAI Platform API key.
- `SCOUTLINE_ALLOWED_ORIGIN` — the exact permanent app address, for example `https://scouting-app.example.com` (no trailing slash).

Optional:

- `OPENAI_LINEUP_MODEL` — defaults to `gpt-5.6-luna`.

Never place the API key in `src/`, GitHub, a browser setting or a committed `.env` file. After adding or changing a Vercel environment variable, redeploy Version 1.6.

The extraction endpoint permits only the configured app origin and limits repeated requests from one network address. For a personal field test, also set a modest monthly project budget in the OpenAI Platform before deploying. Broader user authentication and linking each scout's own AI account remain Version 2 considerations.

## Acceptance checklist

1. Create a match with teams, competition, venue, date and kick-off.
2. Photograph or select each team sheet and run automatic extraction.
3. Correct every uncertain field, confirm goalkeepers, captains and substitutes, then accept both teams.
4. Mark the scouting target or targets and add formation/tactical context.
5. Confirm captain labels and player names remain readable on the pitch.
6. Start the match and record a normal action.
7. Save a general Quick Note without selecting quality.
8. Select quality and use Next to save a player free observation with an optional pitch area.
9. Record a yellow card and test a sent-off player in a non-live test session.
10. Record a substitution and half-time notes.
11. Add target-player rating, strengths and development areas.
12. Finish the match or use Finish Later and resume safely.
13. Download the structured export, AI handoff and safety backup.
14. Restore the safety backup in a test browser and verify the match, players, timeline and clock.
15. Attach the handoff to a separate reporting task and confirm it produces a useful evidence-based report without reconstructing the match manually.

## Deployment

Run `npm test`, then `npm run build`. Commit and push the tested Version 1.6 source to `main`. Vercel uses `npm run build`, publishes `dist`, and deploys `api/extract-lineup.js` as a server function. Confirm the deployment is Ready, open the permanent production domain once online to refresh the Version 1.6 offline cache, and complete the acceptance checklist before the live match.
